# The 24th Group — Operating Rhythm

## Purpose

The Group should be easy to operate and easy to review. This document defines the minimum recurring rhythm for keeping product work, decisions and reporting aligned.

## Source systems

### GitHub
GitHub is the technical record.

Use it for:
- product code
- releases and implementation history
- product context and roadmap files
- technical dependencies and architecture notes

### Asana
Asana is the execution record.

Use it for:
- current tasks
- delivery status
- blockers
- owners
- launch and readiness work

### The24thGroup repository
This repository is the management record.

Use it for:
- Group strategy
- portfolio register
- Group roadmap
- monthly reviews
- operating standards
- Group-level decisions

### Oroko
Oroko can be used as a structured process/documentation workspace for Group operations, product workflows and customer discovery. It should support the operating record, not replace GitHub or Asana as their respective sources of truth.

### Zoho
Zoho is intended to become a broader Group operating backbone for administrative, CRM and reporting needs. Its final architecture is still to be defined and should be documented before deeper consolidation.

## Monthly review cycle

Each month, the Group review should be compiled from:

1. the previous Group roadmap and monthly review
2. each relevant Asana project
3. each product repository and recent commits
4. product context/roadmap files
5. any explicit founder or operating notes for the month

The review should answer four core questions for every product:

1. What did we build or complete?
2. What did we learn?
3. What is blocked or dependent on something else?
4. What are we doing next?

The Group-level summary should also identify:

- changes in portfolio priority
- cross-product dependencies
- shared operational work
- decisions that need founder attention
- anything that materially changed the outlook for a product

## Roles

### Founder
Responsible for:
- strategic direction
- technical decisions where required
- resolving founder-level dependencies
- final review of priorities

### Personal assistant / operating support
Can support by:
- ensuring Asana projects are current
- collecting missing status information
- flagging dependencies
- maintaining the Group archive
- preparing materials needed for the monthly review

### ChatGPT
Used to:
- compare planned work in Asana with actual repository progress
- identify inconsistencies or missing evidence
- compile the monthly review
- summarise changes at product and Group level
- maintain consistent reporting structure

ChatGPT should not infer completion simply because a task exists or a code change appears. Where evidence conflicts, the review should state the conflict.

## Review cadence

### Monthly
Produce and store one Group monthly review.

### Quarterly
Use the monthly reviews to check whether product priorities still make sense. This does not require a separate formal pack unless useful.

### Annually
Produce a short annual review covering:
- what shipped
- what was validated
- what changed strategically
- what was stopped or deferred
- the next year's priorities

## Operating rule

Keep the system lighter than the work it is meant to support. If maintaining a document becomes more work than the decision or reporting value it creates, simplify it.
